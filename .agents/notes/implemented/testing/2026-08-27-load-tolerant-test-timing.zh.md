# Agent Note: 把易受负载影响的测试时序校准为因果顺序，而非碰运气的墙钟时间

Status: implemented

[English](2026-08-27-load-tolerant-test-timing.md) | 中文

## 问题

多进程测试套件在空闲笔记本上通过，在宿主机饱和时失败——完整本地测试、Windows 覆盖率并发或刻意 CPU 风暴期间。四种不同的失败模式都伪装成「超时不稳定」：只按空载 spawn 延迟标定的单用例预算；假设子进程会在固定睡眠内完成某个协议步骤的定长睡眠；被满载宿主的子进程启动时间甩开的生产合并写窗口；以及一个根本不是超时的失败——LSP cancel-grace 测试里固定的 `setTimeout(300)` 中止落在 initialize 握手尚未完成之时，而中止一个挂起的握手按设计会拆除实例，于是 `dead` 在 329ms 内变成 `true`。

## 决策

多进程套件携带按其最重合法运行时间标定的逐套件预算：Git fixture 与 tsx 驱动套件用 20-30 秒，lefthook 安装器的多 worktree 用例用 60 秒，持久化 bash 的 Loader 组合镜像其 pwsh 孪生的 8 秒终端 / 20 秒工具截止时间。纯单元测试保持 5 秒默认值，让真正的挂起仍能快速暴露。

当测试阶段依赖子进程进度时，同步观察因果而非流逝时间。LSP cancel-grace 的服务端脚本在收到 definition 请求时写标记文件，测试轮询到标记才中止，因此请求确定在飞行中，中止永远不会落进握手窗口。

测试作用域的插件配置放宽由生产默认值按吞吐（而非断言）设定的窗口。tool-bash 懒物化测试设置 `writeBatchMaxDelayMs: 60_000`，使 JSONL 活事件合并写窗口（默认 200ms）在满载下无法先于 bash 子进程应答物化文件；回合后的 `sessions.flush` 仍是该测试断言的持久化屏障——这本就是它想固定的约定。同一测试把其 LSP `killGraceMs` 覆盖提升到 10 秒，让满载宿主的子进程响应延迟留在该用例考察的宽限之内。

## 备选方案

**调高全局 vitest testTimeout。** 一刀切的宽裕预算会把快速单元套件里的真死锁藏起来；逐套件预算在要紧处保留快失败语义，只在子进程设定下限的地方放宽。

**保留定长睡眠，只调高外围超时。** LSP 那次失败 329ms 就完成了——任何预算增加都修不了相位倒置。只有因果有序的同步（标记 + 轮询）能让相位确定。

**修改生产默认值（`DEFAULT_WRITE_BATCH_MAX_DELAY_MS`、LSP kill grace）。** 默认值对部署吞吐与拆除节奏是正确的；缺陷在测试标定而非产品行为。生产值保持不变。

**跳过或隔离不稳定用例。** 这些失败是有真实覆盖价值的标定缺陷；跳过等于用覆盖换沉默。

## 后果

九个受影响文件在空闲与刻意 8 CPU 燃烧风暴下都通过（131 通过、2 跳过、0 失败），且这些套件里的真实回归仍会通过行为断言而非时序失败。接受两个代价：多进程套件里的真死锁现在最多要到其逐套件预算才暴露；tool-bash 测试放宽的合并写窗口意味着 flush 屏障语义的真实回归会由显式 `sessions.flush` 断言捕获，而非由碰巧的流逝时间物化捕获——这本来就是更强的约定。
