# Agent Note: Compose an agent preset on a pipeline canvas

Status: implemented

[English](2026-08-23-agent-preset-canvas-composer.md) | 中文

## 问题

row-compose 组合器上线时是「可搜索调色板 + 扁平行 chip 列」：模块名毫无标注——清单里的 `category`/`description` 在表层就被丢弃——而组合列看起来是无序列表，不像 `agent.cordis.yml` 实际上的有序链条。需求正是 Dify 式可视化画布：调色板必须说明每个插件是做什么的，右侧必须支持合理的编排，而「手动组合一个 agent」与「交给创造模式代写」应该是一条流程，而不是两个并列按钮。

## 决策

组合器改造成画布占满整个设置内容区的横向流水线——仍是纯客户端，[row-compose 笔记](2026-08-23-agent-preset-row-compose.zh.md)中的行结构/wire 决策不变：画布在设置顶栏之下铺满分区全部宽高，调色板与检查器则以层级叠加在画布之上，而非并排的侧栏——流水线本身就是工作区，而不是其中的一栏。组合标题（「组合」）作为固定头部位于画布上方、浮层区域之外，因此浮层面板永远不会遮住它。960px 上限对整个设置分区而言都已移除，而不只是组合器：模型、插件与 Agent 预设三个页面都像通用页一样铺满宽度，插件清单的行渲染为响应式 `auto-fill` 卡片网格。调色板是标注过的清单——把 `pluginInventory.list()` 既有条目提纯为 `PaletteModule { moduleName, displayName, category?, description? }`，按 spine 分类分组（未归类的模块共享「其他」桶，它永远不会是真实分类），可在模块名、显示名、分类与描述间搜索，每张卡带类型字形、显示名、分类徽标与截断描述；它默认展开，可收起为画布边缘的标签。画布渲染 Dify 式链条：从「开始」经每个插件行一个节点到「结束」——链序正是写入宿主的那份行序，不存在分支或连边拖拽，因为 `agent.cordis.yml` 是有序行列表，运行时没有任何执行流语义。检查器仅在选中节点时浮于右缘，显示所选节点的分类、显示名、mono 模块名、行 id、描述，以及移除/上移/下移动作；点击画布空白区取消选中。

「创造模式」不再是一张独立卡片，而成为组合器页脚的交接按钮（`让 Agent 帮我搭建/完善`），其语义是「先保存再交接」：保存组合，并在自指的 `cordis` preset 上暂存并开启新会话，像旧卡片一样关闭设置面板。未改动的 preset（`composeBlocker === 'unchanged'`）跳过保存直接交接，因为 `confirmCompose` 此时会静默 no-op。交接按钮只在会话纤维提供 `startCreatorDraft` **且**名单携带 `cordis` 时呈现——能力在使用它的地方被门控。

插入线修复来自 e2e 的发现。drop 槽指示器原本是 keyed fragment 里的 flex child；一旦显示，就会把 fragment 的头元素换成本身的 span——把被拖拽的节点卸下 DOM，Chromium 随即取消原生拖拽，重排彻底不可用。插入线现在是绝对定位的覆盖层，位置由 `slotBoundaries()` 对照 `data-canvas-track` 计算，因此链条在任何拖拽中都不会回流。

随附 preset 的「查看」动作打开只读设计页，取代了原来的原始 YAML 对话框：同一块画布渲染随附链条，一切皆不可编辑——没有调色板、没有标识符或名称字段、没有保存，节点既不能拖拽也没有移除控件。

`apps/web/tests/agent-preset-composer.e2e.ts` 以 keyless 方式驱动真实画布：拖入、追加（最后一个节点的右半）、重排。画布铺满整个舞台，因此 drop 目标远离浮动的调色板——在 1680px 视口里，调色板右缘（约 608px）与 drop 槽中心（约 950px）不相交，调色板拖拽总是释放在画布上，绝不会落在面板上；重排的滚动辅助在短链下已是 no-op。`agent-preset-authoring.e2e.ts` 钉住只读视图（随附链条渲染在画布上、无任何编辑交互）并覆盖交接：拖入一个插件、填标识符、交接，然后断言设置面板关闭、`/api/session.list` 报出 `agentPreset: "cordis"`、以及会话启动前 `my-agent/agent.cordis.yml` 已落盘。

## 备选方案

**Dify 式可分支图。** Dify 的节点以连边组合执行图；agent 组合是一份整体挂载进同一 standing scope 的有序行列表，因此图会呈现格式无法表达的交互（分支、连边拖拽、循环节点）。画布如实渲染链序，而不是发明执行流。

**保留两按钮并存（组合卡 + 创造卡）。** 创造卡唯一的职责是暂存 `cordis` 并开启会话；组合器页脚的交接在保存草稿后做的正是同一件事，独立卡片只会为同一条流程重复入口。无论哪种方式，`cordis` 都能从新会话 chip 选择。

**把插入线做成 flex child。** 它会推动链条，既把指针下的 drop 槽位移走，又——通过在中途卸下被拖拽元素——让 Chromium 取消原生拖拽。在轨道坐标系里绝对定位，才能在零回流的前提下给出实时预览。

## 影响

组合器表层不再与底下的格式相悖：画布的链条就是行序，`config`/`disabled` 原样随 wire 行通过而不被编辑。分区头部位于浮层区域之外，因此浮层面板无法再遮住「组合」标签；只读视图在画布上渲染随附链条，而非原始 YAML 对话框；模型、插件与 Agent 预设三个页面都铺满宽度，插件清单为响应式卡片网格。创造模式从组合器页脚可达，因此空组合提示指向它，名单自身的创建表层仍是「新建 Agent」。插入线脱离了 flex 流，drop 槽预览既不会回流也不会取消拖拽；e2e 必须命中的几何约束已写进测试（调色板右缘与 drop 槽中心不相交，因此调色板拖拽总是释放在画布上）。暂缓事项：交接开启的是空白会话（无 chat 预填），且组合器不提供逐插件的 `config`/`disabled` 编辑器——两者都记入包 README 的已知限制。
