# Agent Note: Compose an agent preset on a flow canvas

Status: implemented

[English](2026-08-23-agent-preset-canvas-composer.md) | 中文

## 问题

row-compose 组合器上线时是「可搜索调色板 + 扁平行 chip 列」：模块名毫无标注——清单里的 `category`/`description` 在表层就被丢弃——而组合列看起来是无序列表，不像 `agent.cordis.yml` 实际上的有序链条。需求正是 Dify 式可视化画布：调色板必须说明每个插件是做什么的，组合必须支持合理的编排，而「手动组合一个 agent」与「交给创造模式代写」应该是一条流程，而不是两个并列按钮。当 preset 组合升级为链式投影的 FlowGraph（[preset-composition-flow-graph 笔记](2026-08-24-preset-composition-flow-graph.zh.md)）之后，特制的流水线表层也成了共享流程画布之外的第二套链渲染器。

## 决策

组合器嵌入共享流程画布——`@deepseek-ai/dsh-client-ui-flow-editor/client` 的 `FlowCanvas`——它占满整个设置内容区，仍是纯客户端，[row-compose 笔记](2026-08-23-agent-preset-row-compose.zh.md)中的行结构/wire 决策不变：画布在设置顶栏之下铺满分区全部宽高，调色板与检查器则以层级叠加在画布之上，而非并排的侧栏——组合本身就是工作区，而不是其中的一栏。组合标题（「组合」）作为固定头部位于画布上方、浮层区域之外，因此浮层面板永远不会遮住它。960px 上限对整个设置分区而言都已移除，而不只是组合器：模型、插件与 Agent 预设三个页面都像通用页一样铺满宽度，插件清单的行渲染为响应式 `auto-fill` 卡片网格。

画布把组合渲染为一条链式图：从「开始」经每个插件行一个 agent 节点到「结束」——链序正是写入宿主的那份行序，不存在分支，因为 `agent.cordis.yml` 是有序行列表，运行时没有任何执行流语义。节点 id 是画布内部的（`agent-1`、`agent-2`、……）；逐节点组合（`module`、`id?`、`group?`、`config?`、`disabled?`、`inject?`）随每个 agent 节点携带。调色板是标注过的已安装模块清单——把 `pluginInventory.list()` 既有条目提纯为 `PaletteModule { moduleName, displayName, category?, description? }`，按 spine 分类分组（未归类的模块共享「其他」桶，它永远不会是真实分类），可在模块名、显示名、分类与描述间搜索，每张卡带类型字形、显示名、分类徽标与截断描述；它默认展开，可收起为画布边缘的标签。

调色板模块落入画布即把该模块追加为下一个链节点——落点决定节点画在哪里，链序则始终追加在末尾。节点可拖拽重新摆放（只改视觉布局，链序不动）；链序本身有两条编辑途径：连线手势——把一个节点的端口拖到另一个节点上，链即重连，使目标紧跟在来源之后——以及检查器的上移/下移。检查器仅在选中节点时浮于右缘，显示所选节点的分类、显示名、mono 模块名、行 id、描述，以及移除/上移/下移动作；Delete 键同样删除当前选中，点击画布空白区取消选中。删除链终端会被拒绝——它们是组合的框架，不是一行。

组合以流程图保存，而非行、更绝不是 YAML 文本或路径：`agentPresets.saveGraph` 携带 `{ agentPreset, graph }`，宿主把图投影回行、对照插件清单重新校验每一个被点名的模块，并在写文件前执行行不变量；`readGraph` 在存储图仍与解析出的行一致时返回它，否则从行重新生成（[preset-composition-flow-graph 笔记](2026-08-24-preset-composition-flow-graph.zh.md)）。流程画布经 `/client` 子路径抵达模块表，该请求声明在包的 `dsh.client.external` 里，客户端 bundle 纯净门才接受这次值导入。

「创造模式」不再是一张独立卡片，而成为组合器页脚的交接按钮（`让 Agent 帮我搭建/完善`），其语义是「先保存再交接」：保存组合，并在自指的 `cordis` preset 上暂存并开启新会话，像旧卡片一样关闭设置面板。未改动的 preset（`composeBlocker === 'unchanged'`）跳过保存直接交接，因为 `confirmCompose` 此时会静默 no-op。交接按钮只在会话纤维提供 `startCreatorDraft` **且**名单携带 `cordis` 时呈现——能力在使用它的地方被门控。

随附 preset 的「查看」动作打开只读设计页：同一块画布渲染随附链条，一切皆不可编辑——没有调色板、没有标识符或名称字段、没有保存，节点既不能拖拽也没有移除控件，因为端口渲染由只读标志门控。

`apps/web/tests/agent-preset-composer.e2e.ts` 以 keyless 方式针对共享画布的 DOM 驱动真实画布：调色板卡片落入画布追加一个节点，端口连线手势重排链条（通过落盘的 `agent.cordis.yml` 行序断言——位置布局看不出来），原地编辑时由检查器移除节点，只读随附链条渲染且无任何编辑交互。`agent-preset-authoring.e2e.ts` 钉住只读视图（随附链条渲染在画布上、无调色板、无字段、无保存、无端口）并覆盖交接：把一个插件拖入画布、填标识符、交接，然后断言设置面板关闭、`/api/session.list` 报出 `agentPreset: "cordis"`、以及会话启动前 `my-agent/agent.cordis.yml` 已落盘。

## 备选方案

**Dify 式可分支图。** Dify 的节点以连边组合执行图；agent 组合是一份整体挂载进同一 standing scope 的有序行列表，因此图会呈现格式无法表达的交互（分支、连边拖拽、循环节点）。画布如实渲染链序，而不是发明执行流；分支是流程引擎的事（B3），preset 格式仍然不表达它。

**保留 PipelineCanvas 的 drop 槽重排。** 流水线按水平落点重排，需要针对槽边界做滚动与几何记账。流程画布自己的连线手势以共享表层已有的词汇表达同一条链重连——「该节点在此节点之后运行」——因此 preset 组合器复用它，而不是再背一套重排机制。

**保留两按钮并存（组合卡 + 创造卡）。** 创造卡唯一的职责是暂存 `cordis` 并开启会话；组合器页脚的交接在保存草稿后做的正是同一件事，独立卡片只会为同一条流程重复入口。无论哪种方式，`cordis` 都能从新会话 chip 选择。

## 影响

组合器表层不再与底下的格式相悖：画布的链条就是行序，跨过传输层的是图——节点位置与逐节点组合——行由宿主投影，浏览器既不写 YAML 文本也不写路径。流程画布成为唯一共享的链式表层，取代了两套并行实现：`PipelineCanvas.tsx`、它的 drop 槽插入线机制与模块 CSS 一并删除，模块表请求声明在 `dsh.client.external` 里，bundle 纯净门因此接受这次值导入。分区头部位于浮层区域之外，因此浮层面板无法再遮住「组合」标签；只读视图在画布上渲染随附链条，而非原始 YAML 对话框；模型、插件与 Agent 预设三个页面都铺满宽度，插件清单为响应式卡片网格。创造模式从组合器页脚可达，因此空组合提示指向它，名单自身的创建表层仍是「新建 Agent」。两条 e2e 已更新到共享画布的 DOM，重排证明改为读取落盘行序而非位置布局。暂缓事项：交接开启的是空白会话（无 chat 预填），组合器不提供逐插件的 `config`/`disabled` 编辑器，且流程画布尚未嵌入子图（B3）——前两者记入包 README 的已知限制。
