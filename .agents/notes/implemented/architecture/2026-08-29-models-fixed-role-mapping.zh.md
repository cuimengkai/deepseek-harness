# Agent Note: pi-ai 的模型列表是固定角色映射——五个角色加一个兜底，由目录预填、由 管理与测试 填充

Status: implemented

[English](2026-08-29-models-fixed-role-mapping.md) | 中文

## 问题

pi-ai 编辑器的模型列表是从 DeepSeek 家族借来的开放式目录编辑器：任意多行，每行编辑 id、显示名、展开区里的容量与模态开关。而用户的要求指明的是 cc-switch 的映射形态——「模型映射需要支持以下几个字段 模型角色/显示名称/实际请求模型/声明支持1M」「每个提供方都需要内置好一些配置信息，如提供方名称/API地址/API格式/提供方的模型」，以及用户可挑选的提供方 logo。一个提供方不是用户照料的行目录：它是一组由本 harness 模型选择器按名寻址的固定角色，外加请求不指名角色时的一个默认兜底；新增提供方时表单应当带着它的预设已知信息打开，而不是空白。开放式行列表表达不了角色，而丢弃目录自身事实的创建流程只会让用户重新誊抄一遍。

## 决策

`ModelListEditor` 渲染六个固定行——五个角色 `Sonnet`、`Opus`、`Fable`、`Haiku`、`Subagent`，再加一个默认兜底模型——按五列表格排布：角色标签、显示名（`name`）、实际请求模型 id（`id`）、获取模型的挑选列、1M 声明（`contextWindow: 1_000_000`）。每条轨道都不量内容解析（fr 份额、固定的挑选轨道），因为每行是自己的网格，一条按内容定尺寸的轨道会在行间漂移——输入框表格欠的正是列对齐。

- **角色行的条目把角色放在自己的 `role` 字段里；显示名是独立的事实。** 填好的 Sonnet 行存 `{ id, role: 'Sonnet', ... }`，名称列独立编辑条目的 `name`——cc-switch 的字段集原样。兜底行的条目是裸的（`{ id }`——无角色无名）：选择器随即显示其 id，读起来正是「模型本身」。行按 `role` 字段找条目；`role` 缺席但 `name` 等于角色名的条目仍认作该角色的条目——字段存在之前映射写入的拼法，保留可读使已存 profile 在升级后幸存。不匹配任何行的条目——未来 schema 新增的字段，或手工写进 `settings.yaml` 的——既不显示也不丢弃：映射只管它的六行，其余条目原样保留，与 DeepSeek 目录编辑器行的同一结构开放性。
- **空映射意味着路由的内置目录，清空一行即移除其条目。** 行只被有意填充；清空一行会拼接移除其条目，而映射头部的重置操作——用户层拥有数组期间提供——把整个数组交还适配器。两个意图两种语义：空覆盖与恢复继承不是同一个手势。
- **1M 声明是一个复选框，只出现在长得出它的角色上。** Sonnet、Opus、Fable、Subagent 与兜底行提供它；Haiku 行渲染一个破折号（这一档模型长不出 1M），Subagent 行的名称列说明它不进选择器。勾选写入 `contextWindow: 1_000_000`；发现或目录披露的容量以同一方式落位，因此 1M 模型显示其声明已勾选。其余容量是适配器报告的普通事实——没有逐行容量输入，因为适配器的路由级兜底会为配置未写明的部分定尺寸。
- **管理与测试 是端点自己的动作，位于 API 地址字段的标签行。** 获取入口坐在 API 地址字段的右缘（映射头部保留第二个），表单密钥被拒绝期间禁用——拿已被表单拒绝的密钥去询问，等于花一个往返去听字段已经说过的话。创建卡片还额外要求端点存在：正在声明的提供方还没有路由，输入的端点是询问唯一能依据的东西，按钮自身的 title 点名这道门。
- **打开弹窗即发起测试请求。** 标题为 管理与测试 的 `ManageTestDialog` 每次打开时挂载，因此询问在挂载时运行一次。它向 `llm.discoverModels` 询问 **表单当前显示** 的端点：已编辑未保存的 base URL、已输入未存储的密钥、表单指名的协议。适配器已描述的路由从自己的注册表作答，因此已存在提供方的卡片可以完全不填端点就询问；只有既无路由又无 base URL 的草稿才无物可问。清单在每个候选的 id 旁显示其显示名与端点披露的容量。应答抵达本身是一个事件：往返耗时印在探测行下方，一条瞬态顶栏——两个提供方表单共享的 `useModelFetchOutcome` hook——报告到达了多少个模型，因此两百个模型的清单不用滚动一个就能回答「到底成没成」。
- **应答是供用户挑选的候选，绝不是背后写配置。** 端点已在服务的候选——当前映射中已有的 id——初始不勾选，因此采纳绝不改写用户已放置的行；全选/取消全选一键切换整个清单。提供方披露的一切随候选进入它填充的行（其 `contextWindow`、`maxTokens`，输入模态写入 pi-ai profile 自有的 `input` 字段——wire 的 role `kinds` 无 pi-ai 对应物，不予携带），候选自身的显示名也随行落位，因为名称列正是端点拼写应在的位置。
- **采纳按显示顺序填充空行——Sonnet 最先，兜底最后。** `adoptIntoMapping` 跳过 id 已在服务的候选。满映射不采纳：采纳按钮禁用并以 `mappingFull` 文案为 title 说明自身，而不是悄悄吞掉一次无操作。
- **每个获取到的候选同时落入该行自己的挑选菜单。** 应答一抵达就交给表单（`onFetched`），因此候选池在弹窗未采纳地关闭后依然幸存。一旦清单存在，每个映射行在其 1M 声明前的一列带一个下拉箭头；打开它列出端点的整个目录——id 旁是端点自己的显示名——一次挑选即以 `pickIntoRow` 执行的同一写入填充该行：id、显示名、候选自身上下文窗口为 1M 时的 1M 声明、以及披露的一切容量。手工挑选的行是郑重的填充，因此行上已有的条目会被替换——与手打 id 同一次写入，少了誊抄。无可列的行不渲染挑选器：未获取过的提供方不显示只会说「请先获取」的控件。

每个提供方路由还携带其预设已知的事实，表单在这些事实上打开：

- **`LlmConfigurableProvider` 携带 `catalogBaseURL`、`catalogApi`、`catalogModels`。** pi-ai 适配器从已安装目录填充——内置端点、路由全部模型共享的唯一协议（不一致时缺席）、目录顺序的模型本身。它们作为 `ConfigurableProviderView` 的字段过 wire、由 apiproxy schema 校验，目录一无所知的路由缺席。
- **新增流程从选中的预设预填表单。** `ProviderEditor` 以 `prefill` 打开，播种草稿的显示名、base URL、协议，并经 `prefillMapping` 播种映射：每个角色取目录中 id 含角色名的首个模型（sonnet、opus、……），兜底取未被角色消费的首个模型，目录的名称与容量随之落位。已填的行保留；编辑流程一概不动，因此未触碰的表单什么都不写。清空后的 base URL 字段占位符把目录端点显示为「提供方默认」。
- **提供方的 logo 是按提供方挑选的内置 SVG 标记。** `ProviderLogo` 先渲染 profile 自有的 `icon` 字段，其次路由 id 映射到的内置标记（`ROUTE_ICONS`），最后显示名首字符落在按路由 id 哈希的调色板颜色上——卡片网格原有的字母头像，保留为兜底使开放路由集无需附带资源。SVG 及其显示名自 cc-switch 图标集 vendored 进 `provider-icons.ts`。
- **图标从弹窗挑选。** `IconField` 在创建卡片的 Provider ID 上方、编辑表单顶部居中放置 logo 按钮；点击打开 `IconPickerDialog`——带搜索与预览的内置标记网格、清除 profile `icon` 的恢复默认操作（内置路由回到其自带标记），写入与任何编辑一样落在 profile 的 `icon` 字段。弹窗铺满设置面板宽度的大半（`width: min(760px, 100%)`），让图标集读作网格而非细条，并以编辑/选择弹窗同款的 content/body `min-height: 0` 链封顶于视口高度，短窗口下收缩并滚动网格，而不是卡片长过固定遮罩、把底栏留在屏幕之外。宽度必须写在弹窗自己的 `width` 上而非 `max-width`：Modal 卡片声明了 `width: min(380px, 100%)`，上限撑不开它——在 chromium 实测，规则写着 `max-width: 760px` 时弹窗仍渲染 380px。其滚动网格保留滚动条槽（`scrollbar-gutter: stable`），因为主题占空间的滚动条否则会盖住最右列的图标格——分节里每个滚动容器都做同一保留。
- **API 协议下拉框铺满其字段。** `select` 输入占据字段的全部宽度（`select.input { width: 100% }`），与表单上其余控件一致，而不是收缩到内容宽度。

双语的 locale 键：`modelMapping`、`defaultFallbackModel`、`mappingFull`、`modelRoleLabel`、`requestModelLabel`、`modelOneMHeader`、`subagentHiddenName`、选择器的 `icon*` 一组、映射头部按钮的 `fetchModels`、以及 管理与测试 一组——`manageAndTest`（API 地址字段的按钮与弹窗标题）、`manageTestDescription`、`fetchToast`（`{count}`）、`fetchLatency`（`{ms}`）、`modelPickerLabel`（每行的下拉箭头）。

## 备选方案

- **保留开放式目录编辑器**——否决：用户点名了四列与角色。角色是本 harness 模型选择器按名寻址的东西；任意行列表没有角色模型 id 的归属位置，每个提供方表单都会让用户仅凭显示名自行推导哪行对应哪个角色。
- **把角色存为条目的显示名**——否决：名称列是独立的事实。让 `name` 兼职携带角色，端点或用户想让选择器显示的名字就没有落点，读回已存 profile 还得猜哪些名字是角色。
- **映射行可编辑容量**——否决：适配器的路由级兜底已为条目按 id 单独描述的模型定尺寸；发现会把披露的容量带入条目。1M 声明是唯一带复选框的容量，因为它是用户拥有的断言——端点的披露会填上它，手工勾选则声明端点没有说的事。
- **获取时采纳全部发现候选**——否决：应答是供用户挑选的候选。背着用户写配置会在用户从未看到哪个 id 落位的情况下重指角色模型，而两百个模型的清单会覆盖用户调好的映射。
- **什么都不预填、让用户重打一遍预设**——否决：目录条目已经知道选中预设的端点、协议与模型。把这些丢在地板上会把新增流程变成誊抄练习；播种草稿只是读一遍页面本来就持有的字段。
- **logo 作为按路由 id 解析的图片资源发布**——否决：路由集是开放的（手工声明的网关没有标记），而提供方可能想要与其路由不同的标记。内置集加 profile 的 `icon` 字段让内置路由有自己的标记、自定义路由有选择、未知路由有字母头像。
- **行已填满时静默无操作**——否决：禁用并点名原因（`mappingFull`）的按钮说明了该清什么；点了按钮却什么都没写就关掉弹窗会被读成成功。

## 后果

- pi-ai 表面失去了添加行命令、容量展开与模态开关；DeepSeek 家族保留其表格形态（`DeepSeekModelsEditor`），两族的模型编辑器从此是种类之差而非附加项之差——目录是照料的，映射是指派的。
- 条目以其他名字命名的已存 profile 能在编辑中幸存但永不在卡片上可见；写入门仍裁决那些条目，因此不可见的非法条目会让写入以其数组位置失败。
- 创建卡片的「至少一个映射模型」门现在读作「填六行中任意一行」——仅一个裸兜底条目即是合法创建，由路由的兜底定尺寸。
- 目录载荷随目录增长：每个休眠路由在配置之前就把它的模型带给浏览器，新增弹窗把这些事实渲染为预填好的表单。
- 内置图标集是一项维护事实：cc-switch 更新后整体重 vendor `provider-icons.ts`，已存 profile 中的未知图标名回退到字母头像而不是失败。
- 获取弹窗的探测中、空清单与被拒传输各自呈现在弹窗里，而行在弹窗之后等待手工录入——无法询问的提供方是绕行，不是绝路。
- 应答是表单保留的事实，不只是弹窗状态：获取到的候选池比弹窗活得久（再次打开会重新询问并刷新），而顶栏/耗时上报是一条长清单唯一「成功了」的反馈。
- 嵌入式新增流程的挑选与编辑弹窗渲染表单 portal 取消/提交行的 footer slot（该姿态归[嵌入式表单笔记](2026-08-28-models-add-dialog-embedded-form.zh.md)所有）；映射与其弹窗原样嵌在同样的弹窗内。

## 验证

- `provider-form.client.spec.tsx`——`model mapping` 用例：每个填充行存为适配器服务的条目（条目上的 `role`，名称独立）；已存 profile 以两种拼法读回各行；两行共享一个 id 时点名后出现的行；继承/自定义元信息与清空对重置保持区分。`fetch model list` 用例：以未存储密钥询问表单显示的端点；携带 profile 指名的协议；API 地址字段自己的 管理与测试 打开同一询问；顶栏上报获取数量与往返耗时；一行经其挑选菜单一次点击填充——id、显示名、1M 声明、披露的容量——且写入携带它们；仅采纳勾选的候选并保留用户已调好的行及其显示名；五个角色按序填充且兜底最后；行已填满时拒绝采纳；提供方无法询问时行仍可编辑；空清单与被拒传输都有上报；已配置路由无端点也可询问；创建卡片有端点后才询问；取消关闭且不采纳；候选可关掉再勾回；全选与清空一键完成。字段作用域用例固定表单顺序——logo、身份、端点、密钥、表单上的映射，其余折叠在 高级选项 之后。
- `components.client.spec.tsx`——卡片/头像用例现在断言两种标记：图标集没有标记的路由佩戴字母头像，知道的路由佩戴内置 SVG；新增流程经嵌入自定义表单与编辑器 footer slot 固定。`styles.client.spec.ts` 固定映射行（五条不量内容的轨道，标题与每行一致）、字段头、滚动条槽与全宽 select 的样式表契约。
- `llm-pi-ai` 的 `dynamic-config.spec.ts` 断言目录条目为内置路由携带 `catalogBaseURL`、`catalogApi`、`catalogModels`；类型以 `type-equiv` 原样贴在 [llm-streaming](../../../../docs/subsystems/llm-streaming.zh.md)，生成的 Cordis 类型目录随之刷新。
- `ui-settings-models` 套件 234/234；`llm-pi-ai` 与 `apiproxy` 套件绿；包内 `tsc -b` 绿；`pnpm run lint` 绿；`pnpm run doc-sync` 绿。
