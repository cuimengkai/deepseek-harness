# Agent Note: Compose an agent preset on a flow canvas

Status: implemented

English | [中文](2026-08-23-agent-preset-canvas-composer.zh.md)

## Problem

The row-compose composer shipped as a searchable palette beside a flat chip column, but the module names had no annotation — the inventory's `category`/`description` were discarded at the surface — and the composition column read as an unordered list, not as the ordered chain `agent.cordis.yml` actually is. The request was a Dify-style visual canvas: the palette must say what each plugin does, the composition must support real orchestration, and composing an agent and letting Creator mode draft one should be one flow rather than two parallel buttons. Once the preset composition became a chain-projected FlowGraph ([preset-composition-flow-graph note](2026-08-24-preset-composition-flow-graph.md)), the bespoke pipeline surface was also a second chain renderer duplicating what the shared flow canvas already does.

## Decision

The composer embeds the shared flow canvas — `FlowCanvas` from `@deepseek-ai/dsh-client-ui-flow-editor/client` — which owns the whole settings content area, still pure client, with the row-structure/wire decision of the [row-compose note](2026-08-23-agent-preset-row-compose.md) unchanged: the canvas fills the section's full width and height under the settings top bar, and the palette and inspector float over it as layers rather than side columns — the composition is the workspace, not a column in one. The composition's head label (`组合`) sits above the canvas as a fixed head, outside the layered region, so a floating panel never covers it. The shared 960px cap is gone from the settings sections as a whole, not just the composer: Models, Plugins, and Agent presets all fill the width like General, and the Plugins inventory renders its rows as a responsive `auto-fill` card grid.

The canvas renders the composition as a chain graph from Start through one agent node per plugin row to End: chain order IS the row order written to the host, and there is no branching because `agent.cordis.yml` is an ordered row list with no runtime execution-flow semantics. Node ids are canvas-internal (`agent-1`, `agent-2`, …); the per-node composition (`module`, `id?`, `group?`, `config?`, `disabled?`, `inject?`) rides on each agent node. The palette is the annotated installed-module inventory — `PaletteModule { moduleName, displayName, category?, description? }` surfaced from `pluginInventory.list()`'s existing entries, grouped by spine category (uncategorized modules share the `其他` bucket, which is never a real category), searchable across module name, display name, category, and description, with a typed glyph, display name, category badge, and clamped description per card; it is expanded by default and collapses to a tab on the canvas edge.

A palette module drops onto the canvas to append it as the next chain node — the drop position is where the node is drawn, the chain order appends it last. Nodes drag to be repositioned on the canvas (a visual layout only; the chain order is untouched), and the order itself is edited two ways: the connect gesture — dragging a node's port onto another node relinks the chain so the target runs right after the source — and the inspector's move-up/down. The inspector floats over the right edge only while a node is selected, showing the selected node's category, display name, mono module name, row id, description, and remove/move-up/move-down actions; the Delete key removes the selection too, and clicking the canvas background deselects. Removing the chain terminals is refused — they are the composition's frame, not a row.

The composition is saved as a flow graph, not as rows and never as YAML text or a path: `agentPresets.saveGraph` carries `{ agentPreset, graph }`, the host projects the graph back to rows, re-checks every named module against the plugin inventory, and enforces the row invariants before the file is touched; `readGraph` returns the stored graph when it still matches the parsed rows and otherwise regenerates from them ([preset-composition-flow-graph note](2026-08-24-preset-composition-flow-graph.md)). The flow canvas reaches the module table through the `/client` subpath, which is declared in the package's `dsh.client.external` so the client bundle purity gate accepts the value import.

Creator mode stops being a standalone card and becomes the composer's footer handoff (`让 Agent 帮我搭建/完善`), which is save-then-handoff: it saves the composition and starts a session staged on the self-referential `cordis` preset, closing the settings panel as the old card did. An untouched preset (`composeBlocker === 'unchanged'`) skips the save and hands off directly, because `confirmCompose` otherwise no-ops. The handoff is present only when the conversation fiber provides `startCreatorDraft` AND the roster carries `cordis`, so the capability is gated where it is used.

A shipped preset's `查看` action opens the read-only design page: the same canvas renders the shipped chain with nothing editable — no palette, no id or name fields, no save, and the nodes neither drag nor offer a remove control, because the port render is gated on the read-only flag.

`apps/web/tests/agent-preset-composer.e2e.ts` drives the real canvas keylessly against the shared canvas DOM: a palette card drops onto the canvas to append a node, a port-connect gesture reorders the chain (asserted through the saved `agent.cordis.yml` row order, which the positional layout cannot show), the inspector removes a node on the in-place edit, and the read-only shipped chain renders with no edit affordances. `agent-preset-authoring.e2e.ts` pins the read-only view (the shipped chain renders on the canvas with no palette, no fields, no save, and no ports) and covers the handoff: drag one plugin onto the canvas, fill the id, hand off, then assert the settings panel closes, `/api/session.list` reports `agentPreset: "cordis"`, and `my-agent/agent.cordis.yml` landed on disk before the session started.

## Alternatives considered

**Dify-style branchable graph.** Dify's nodes compose execution graphs with edges; an agent composition is an ordered row list mounted wholesale into one standing scope, so a graph would present affordances (branching, edge-dragging, loop nodes) the format cannot express. The canvas renders the chain order honestly instead of inventing flow; branching is a flow-engine concern (B3) that the preset format still does not express.

**Keep PipelineCanvas's drop-slot reordering.** The pipeline reordered by horizontal drop position, which needed scroll and geometry bookkeeping against the slot boundaries. The flow canvas's own connect gesture expresses the same chain relink — "this node runs right after that one" — in the vocabulary the shared surface already provides, so the preset composer reuses it instead of carrying a second reorder mechanism.

**Keep the two-button split (composer card + Creator card).** The creator card's only job was staging `cordis` and starting a session; the composer's footer handoff does the same after saving the draft, so a separate card would duplicate entry points for the same flow. `cordis` remains selectable from the new-session chip either way.

## Consequences

The composer surface no longer contradicts the format underneath: the canvas's chain IS the row order, and the graph — node positions and the per-node composition — is what crosses the wire, with rows as the host's projection and the browser writing neither YAML text nor a path. The flow canvas is one shared chain surface instead of two parallel implementations: `PipelineCanvas.tsx`, its drop-slot insertion-line machinery, and its module CSS are deleted, and the module-table request is declared in `dsh.client.external` so the bundle purity gate accepts the value import. The section head is outside the layered region, so a floating panel can no longer cover the `组合` label; the read-only view renders the shipped chain on the canvas instead of a raw-YAML dialog; and the Models, Plugins, and Agent-preset sections all fill the width like General, with the Plugins inventory as a responsive card grid. Creator mode is reachable from the composer footer, so the empty-composition hint points at it and the roster's own create surface stays `新建 Agent`. The e2e lanes were updated to the shared canvas DOM, so the reorder proof now reads the saved row order rather than the positional layout. Deferred: the handoff starts a blank session (no chat prefill), the composer offers no per-plugin `config`/`disabled` editor, and the flow canvas does not yet embed sub-graphs (B3) — the first two recorded in the package README's Known Limitations.
