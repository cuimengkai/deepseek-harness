# @deepseek-ai/dsh-client-ui-project-insight

English | [中文](README.zh.md)

The develop mode's insight tabs: five `conversation.view` registrations that render the session project's committed project-insight document. Each tab shows one of the scanned sections — module dependency topology, component dependencies, tech stack, components, and agent-related technology — in ring order after the trajectory tab. The prompts section renders inside the agent-tech tab's prompts sub-tab, so it owns no dedicated tab. The document and its sections are produced by the host service [`@deepseek-ai/dsh-project-insight`](../../insight/project-insight/README.md).

The tabs are gated to the `develop` agent preset through the per-session `modes` filter on the conversation-view ring: the filter shows a tab only while the session's resolved preset is a member of its `modes`, so switching a session into develop mode shows the five tabs by default and switching out hides them. Entries that declare no `modes` (chat, trajectory) always show.

Each tab owns a per-session `ProjectInsightController` that reads the session's document through the privileged `projectInsight.read` RPC (reading project files is reconnaissance), keyed off the session's current `cwd`. A fresh document renders immediately; `none` and `stale` mean the host may still be scanning, so the controller re-reads on a two-second interval until the wire reports `fresh`. A generation counter makes the latest `load` (or `dispose`) supersede every older in-flight read and scheduled poll, so a session switch never flashes a previous session's document. While the document is absent or being re-scanned, the tab renders a centered frame — a spinner beside the status copy for the busy states, plain copy for unscanned and unreadable — matching the app's other loading presentations.

The two dependency sections render a full-bleed React Flow dependency graph — pan, zoom, and wheel come from the library, and mutual-import cycle members highlight in red — with the complete module or component list floating over the canvas's left edge as a translucent panel and the selected file's content drawer floating over its right edge. Every node card carries its file-type category as its border, text, and background tint (TypeScript blue, JavaScript amber, component green, style brand, neutral otherwise), and the selected node takes the strongest ring — the brand border, fill, and a 3px ring — so it reads through the whole canvas. The list, drawer, and canvas stay in sync in both directions: hovering a list row rings its node, and selecting one centers the canvas on its node at focus zoom with the node's edges accented and opens the drawer on that file's content (embedded content when the documents pool carries the file, its row JSON otherwise); hovering or tapping a canvas node highlights and scrolls the row into view and opens the same drawer; tapping the background or closing the drawer clears the selection. Rows outside the bounded node set stay listed but dimmed as "not in graph"; the panel closes to give the canvas the full width. The module graph drops external leaves and un-emitted targets, labels through path aliases, and caps nodes by degree and edges by count; a toolbar caption names what each cap omitted, and a section whose edge set is empty falls back to the explorer tree instead of a canvas.

The tech-stack, components, and agent-tech sections render as a left-tree/right-detail explorer: the left pane is the derived group/leaf tree (tech stack: runtimes, manifests, dependencies by manifest category, source files by language; components: one directory group per parent directory; agent-tech inventory: one group per file role plus a tools root; the skills, MCP, and prompts collections: one directory group per document), and the right pane renders the selected group's JSON through the shiki-highlighted `CodeBlock` — selecting any file row instead renders that file's embedded content: markdown documents through `MarkdownText` (whose fenced code blocks carry the shiki highlight), other files through the grammar-hinted `CodeBlock` (ts/tsx, js/jsx, vue, svelte, yaml, json, toml, ini, and more by extension, plain otherwise). File content resolves through the shared documents pool every tab shares; the agent-tech inventory layers its own collections over the pool so an MCP config's redacted embed is never shadowed by its verbatim source, and a row the document caps excluded falls back to its row metadata JSON, with a tool leaf resolving its referenced file's content. The agent-tech section renders sub-tabs over its inventory and its embedded content collections; the section and the explorer opt into the conversation composer overlay, so the tab bars and panes stay pinned while the tab's content scrolls under them, and every scroller reserves the floating composer seat's height.

## Model Experience

None, as the tabs render the committed document and never reach the model; the `projectInsight.read` RPC reads project files but produces no model input.

#### KV Cache effect

None — the tabs add no prompt content and the read result is not part of any model request.

## Known Limitations and Deferred Work

- **Dependency graphs are capped** — the module graph keeps only the highest-degree nodes and a bounded edge count, so a very large project's visual is partial; the floating complete list is the completeness fallback and the toolbar caption names what each cap omitted.
- **Group detail is JSON, not prose** — the explorer's right pane renders a selected group's committed rows as highlighted JSON; only file and document rows get the content rendering.
- **Prompts markdown comes from the agent-tech embed** — the metadata-only `prompts` section carries no content, so the agent-tech prompts sub-tab renders the section's embedded prompt collection, bounded to its first rows and byte caps.
- **Freshness lags file changes** — a `stale` document re-reads every two seconds until the host reports `fresh`, so a scan must complete and the poll interval elapse before the tab updates.
- **No project, no tabs** — a session without a `cwd` has nothing to scan and the tabs render nothing.
- **Develop-only** — the tabs stay hidden unless the session's resolved preset is `develop`; other presets show no insight tabs from this package.
- **Embedded documents are bounded** — the agent-tech content collections and the shared documents pool cap rows per collection, bytes per document, and bytes in total (schema constants), so a project with many or large files shows only the first rows; MCP `env` values arrive redacted.
